## 2. SYSTEMS THINKING MODEL

I approach problems using a consistent mental model:

1. **Define the system boundary** – What is inside the system. What is explicitly out.
2. **Identify roles, not tools** – Every component has a responsibility. Tools are interchangeable.
3. **Separate execution from reasoning** – Fast paths handle throughput. Slow paths handle correctness.
4. **Assume failure by default** – Design detection, containment, and recovery before optimization.
5. **Constrain behavior explicitly** – Guardrails outperform instructions.

## 3. REPRESENTATIVE SYSTEM: AI-NATIVE RUNTIME

### Problem
LLMs are powerful but unreliable. They hallucinate, loop, drift, and blur responsibilities.

### System Objective
Create a reliable AI runtime where probabilistic models can be used safely inside deterministic workflows.

### Architecture Summary
- Layered execution model
- Role-based agents
- Deterministic logic layer supervising probabilistic outputs
- Explicit failure detection and rejection paths

### Key Design Decisions
- Separate "fast interaction" from "deep reasoning" to control cost and latency
- Enforce agent contracts to prevent scope creep
- Treat hallucination as a detectable failure mode, not an edge case
- Centralize orchestration to prevent agent cross-contamination

### Outcome
- Predictable behavior from non-deterministic components
- Lower cognitive load for users
- Scalable architecture suitable for multiple domains
